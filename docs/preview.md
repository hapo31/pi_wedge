# プレビュー

画面に表示する文言は[開発規約の「ユーザー向け文言」](../AGENTS.md#ユーザー向け文言)に従う。画面と利用目的から伝わる説明を省き、冗長な表現や誇張を加えない。

React + TypeScript、Three.jsベースの[gcode-preview](https://github.com/xyz-tools/gcode-preview)を採用。テキストG-codeを解析・描画するので.gcode.3mfはサーバーのyauzlアダプターで選択した`Metadata/plate_N.gcode`を抽出する。最大100枚、番号の欠番に対応する。ZIPをディスクへ展開せず、エントリ数・compressed/uncompressed size・実読取byteを制限。暗号化、不正構造、期待パス不存在は422。

`/preview/{uuid}`: 大きな3D viewport、右側ファイル名/UUID/推定時間/材料/接続状態、下部レイヤースライダー。180×180×180mm build volume、回転/ズーム/pan、単一レイヤー/積層表示、travel toggle。印刷は別の目立つボタン→ネイティブ確認ダイアログ→API、実行中disable、恒久冪等キー使用。unknownは成功と表示しない。

AIから受け取った `/preview/{uuid}` を開くだけで、指定した表示名（なければ元モデル名）・統計・3Dツールパスを自動表示する。トークン入力、APIリンク、UUIDの目立つ表示を省き、スマホで確認して印刷開始する用途に絞る。UIにAPI_TOKENを埋め込まず、データは専用の `/preview/{uuid}/data`・`gcode`・`download` から取得。元モデル本体は公開しない。`/history` と `/history/data` は信頼するLANへreadyスライスの名前・日時・形式・推定時間・フィラメント量・結果UUIDだけをページ分割して公開する。403/404/422/413を日本語で表示。

「印刷」は確認後にAMS供給設定JSON（外部スプールは空本文も対応）をPOSTで `/preview/{uuid}/print` へ送信。同一OriginとIdempotency-Keyをサーバーで検証し、認証済みAI APIと同じPrinterServiceを使用する。Originがない/一致しない要求は403、CORSは許可しない。これは信頼するLANでの運用を前提とする。

操作は「印刷」「ダウンロード」、同じ印刷要求の照会は「結果を確認」と表示する。用途の説明や転送の内部手順、操作ID、フッターの補足は表示しない。印刷前の確認は供給元・選択スロットの材料と色・PLAスライス設定・ベッドレベリング・ベッド/プレートを表示する。acceptedは「受付済み」、unknownは「結果不明」とし、印刷中・印刷完了と混同しない。プリンターの設定有無は接続確認の結果として表示しない。エラーはコードに応じた日本語で原因・対処を表示し、APIや描画ライブラリの内部メッセージは直接表示しない。

スマホからは同じLANの `http://ホスト名.local:3000/preview/{uuid}`（mDNS稼働時）または `http://LAN-IP:3000/preview/{uuid}` を使う。APIサーバーの既定待ち受けは `HOST=0.0.0.0`。APIのURLは相対パスなのでアクセスしたホスト名/IPのままデータを取得できる。Viteの開発サーバーを起動せず、ビルド済みUIをAPIサーバーから配信する構成で利用可能。

負荷対策: サーバーMAX_PREVIEW_MB既定32（展開後のMiB）、browser response上限、1行のコメント64KiB・コマンド4KiB上限、ZIP構造検証、キャンセルとdispose。総行数と1レイヤーのコマンド数で拒否せず、容量内のG-code全体を解析・描画する。容量上限超過はdownloadを案内。描画用geometryは最終的にブラウザ/GPUに残るため、全端末での最大容量の表示を保証しない。モバイルでは統計を下へ配置。

確認: raw/container同じツールパス、無効ファイル/ZIP bomb拒否、レイヤースライダー反映、build volume、統計null表示、確認キャンセルで送信なし、二重クリック1送信、失敗・unknown表示。WebGL実ブラウザ検証と型/ビルドを別々に記録。

実装は元テキストを走査してparserへ最大1,000行ずつ投入し、全行の配列を保持しない。描画用に不要なコメント・サムネイルを除き、解析/描画が8msの処理枠を使ったら次のフレームへyieldする。ライブラリのrenderLayerで移動/円弧を解釈し、1レイヤーの内部も最大1,000コマンドずつgeometryへ変換する。完了したレイヤーのコマンドを解放し、同色のmaterialを共有する。中断時は処理を停止し、geometry/materialを解放する。レイヤー変更は既存geometryの可視性変更だけで再解析/再生成しない。feature/速度による色分けは未実装、押出/移動の色とtravel切替を実装。

旧250,000行/レイヤー20,000コマンド制限には、実測に基づく限界値の記録がなかった。コメントを含む総行数では描画負荷も決まらないため、全体表示の要望に合わせて撤廃した。容量・1行長・ZIPの制限は継続し、サーバーのG-code検証も10,000行ごとにevent loopへyieldする。

初期視点とviewportのサイズ変更時は、全レイヤーの境界からカメラの注視点と距離を求め、モデル全体が収まるようにする。単一レイヤーへの切替では視点を変更しない。

Orca/Prusa系のCHANGE_LAYER/LAYER_CHANGEがある場合、開始前のパージ押出をプレビュー入力から除去し、起動時の移動/押出モードを保持する。実成果物の100レイヤー20mm cubeで層表示を検証。コメントのない通常G-codeはライブラリのZ/押出による層推定を利用する。

印刷ボタン上にAMS Lite接続状態と各スロットの材料・色・装填状態・使用中の供給元を表示する。更新ボタンで状態を読み直す。外部スプール/AMSとスロットを今回の印刷に選択できる。空・状態不明・既知のPLA以外のスロットは選べない。読み取り失敗は接続済みと表示せず、選択済みAMSでの新規開始を無効にする。送信中・受付済み・結果不明・応答不達時は設定を固定し、キーと設定をlocalStorageへ保持する。

## 複数プレートとUUID

3MFをまとめるプレートUUIDと、各枚を選ぶプレビューUUIDをSQLiteに保存する。正規URLは`/preview/{plateUUID}/{previewUUID}`。`/preview/{plateUUID}`は1枚目へ302、従来の結果UUIDだけのURLも対応するネストURLへ302で移動する。ID欄で両UUIDを参照でき、履歴には割当済みの両IDと枚数を返す。初回プレビュー時に既存結果にもIDを割り当て、その後は変えない。履歴はSQLiteだけを読み、未初期化の結果は従来のUUIDリンクを使う。オブジェクトの取得失敗で一覧全体を止めない。

複数枚の場合だけ3Dビュー下部に各枚のサムネイルを表示する。ヘッドレスOrcaがPNGを含まない場合も扱えるよう、G-codeから上面図を生成し、描線は最大4096本に間引く。生成は1000行単位で処理を譲り、中断を確認する。抽出からSVG生成まで同時処理上限2を維持する。ブラウザは1枚ずつ取得する。切替直後に旧処理が残った場合、GETの503 `preview_busy`だけを最大30回（待機合計28.75秒）再取得し、切替時は待機も中断する。切替・直接アクセス・再読込・戻る/進むはネストしたプレビューUUIDに従い、統計・レイヤー・確認対象を切り替える。指定枚の不在や別プレートへの所属は404。印刷の保存キーはプレビューUUIDごとに独立させ、変更前の結果不明操作を自動再送しない。

ブラウザのdata/gcode/thumbnail/printはプレートUUIDに任意の`previewId`クエリを添えて選択する。本文のAMS限定、Origin、容量上限は維持する。公開dataは限定したファイル情報と各UUID・番号・統計だけで、スライス設定と元モデルIDは含めない。ダウンロードはプレート全体、印刷は選択したプレビューの保存済み成果物の該当G-codeを使う。

## ブラウザのルーティングと状態

TanStack Routerのコード定義を`web/src/router.tsx`に置く。`/history`は履歴、`/preview/$plateId`はヘッダーとプレート一覧を持つ親レイアウト、`$previewId`はViewer・統計・AMS・印刷操作を持つ子ルート。親はプレートUUIDが変わったときだけ再マウントし、子はプレビューUUIDで再マウントする。同じ集合内の切替では一覧のDOM・画像URL・横スクロールを保持し、読み込み表示とViewerに同じ高さを割り当てる。選択先の取得に失敗しても一覧を残す。

通常の縦スクロールバー用の幅を常時確保する。AMS表示などでサイドバーが長くなる場合は、同じ集合内で実測した最大高を親に保持して、切替中にも文書のスクロール範囲を確保する。読み込み中にページが短くなってスクロール位置が上へ戻ることを防ぐため、短い情報へ移動した後はサイドバー下に余白が残ることがある。別の集合へ移動すると確保高をリセットする。

正規URLへの履歴リンクとプレート切替にはRouterを使う。未初期化の履歴とID欄の短縮URLは通常のドキュメント遷移とし、既存のHonoの302で正規URLに解決する。印刷操作の保存・復元単位はプレビューUUIDのまま。切替で古いGETを中断し、遅れて返った結果を共有レイアウトへ反映しない。

## loaderとTanStack Query

`@tanstack/react-query` 5.104.5を使用し、取得を開始する4か所のeffectをqueryへ置換した。GETの通信処理は`web/src/preview-queries.ts`、キー・取得条件は`query-options.ts`、QueryClientとloaderの受渡しは`query-client.ts`に置く。

| データ     | キー                                   | 取得・保持                                                                                                                                                                                           |
| ---------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| メタデータ | `preview-data / plateId / previewId`   | 子loaderがQueryObserverを通して最新取得を待つ。集合一覧と選択枚の統計を兼ねるため両UUIDを含める。画面への受渡し用に非購読後30秒保持し、hookのマウントで再取得しない。鮮度は0で、再進入時は再取得する |
| G-code     | `preview-text / plateId / previewId`   | メタデータ成功後、子の`useQuery`で取得する。32MiB上限を維持。選択中は再取得せず、非購読後の`gcTime: 0`で破棄対象にする。本文はRouterのloaderDataへ入れない                                           |
| AMS        | `printer-status / plateId / previewId` | プリンター設定ありの場合に進入時と明示的な更新で取得。非購読後は破棄。失敗時はキャッシュに残る旧snapshotを供給情報として使用しない                                                                   |
| サムネイル | `thumbnail / plateId / previewId`      | 親配下の各枚が購読。`SerialFetch`で通信・再試行・Blob取得を同時数1に制限し、中断した待機要求は送信しない。Blob URLの生成・破棄は各コンポーネントのeffectで行う                                       |
| 履歴       | `history / q`                          | 検証済みURL検索語を使う`useInfiniteQuery`。先頭も追加ページもQueryが取得・蓄積し、cursorは`pageParam`で扱う。検索変更・離脱後は非購読のページを破棄する                                              |

QueryClientはアプリで一つを共有する。loaderは取得中だけQueryObserverを購読し、ルート中止時に解除する。他のloaderや画面が同じqueryを購読中なら取得を継続し、最後の購読がなくなった場合だけQueryのsignalで中断する。pending/errorは子に閉じ、既存の一覧・画像URL・スクロール範囲を保持する。本文の取得失敗はメタデータの表示を妨げない。

`/history?q=...`の検索語はZodでtrim・80文字・制御文字禁止を検証し、未知キーと文字列以外は拒否する。検索でルートを再マウントし、入力欄も戻る/進むに追従する。追加読込中も別の検索を実行でき、古い検索の応答は新しい一覧へ混ぜない。追加失敗時は既存ページを残し、「さらに表示」で再試行できる。履歴のloaderによる先読みは行わず、初期取得もhookに統合した。

全queryは`retry: false`、フォーカス・再接続時の自動取得なし、`networkMode: 'always'`とする。既存のGET専用503 `preview_busy`再試行だけを維持し、Queryのsignalを通信・ストリーム・再試行待機へ渡す。全枚のG-code先読み、Query永続化、自動ポーリングは行わない。`gcTime: 0`はJavaScriptヒープの即時解放を保証しないため、Viewerの解析・WebGL資源の破棄も引き続き行う。

ダウンロードはクリック時の処理、印刷POST・確認・永続冪等キーは`PrintController`の責務とする。DOM計測、Blob URL、印刷状態復元などのeffectは残す。検討の経緯は[Query併用案](query-migration-research.md)、実際の検証結果は[検証記録](verification.md)を参照。
